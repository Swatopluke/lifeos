# LifeOS

A single-page personal-tracking web app: sleep, intake (food / stimulants / alcohol), body metrics, training, and a curated "world" feed (weather, dev, news). Data is stored in a remote **Supabase** (Postgres) backend and visualized with **Chart.js**.

## Stack

- **Frontend:** vanilla JavaScript ES modules (`js/*.js`), `index.html`, `css/styles.css`. No framework, no bundler, no build step.
- **Backend:** hosted Supabase (Postgres + Auth). The data layer is remote — there are **no local migrations**.
- **Viz:** Chart.js v4 loaded from CDN in `index.html`.
- **Auth:** Supabase email/password via `js/auth.js`; client built in `js/config.js`.

## Repository layout

- `index.html` — app shell: login gate, six sections (overview / sleep / body / training / intake / world), bottom nav, log-sheet modal. Loads `js/nav.js` + `js/app.js` as module entry points.
- `css/styles.css` — theme tokens (CSS vars `--sleep/--caf/--booze/--food/--energy/--weight/--dim/--faint/--border/--surface2`) and layout.
- `js/config.js` — Supabase client (`sb`) + seed data (`SEED_PROJECTS`, `SEED_EVENTS`) used until matching tables exist.
- `js/utils.js` — shared helpers (`$`, `todayISO`, `daysAgoISO`, `budDay`, `toast`, `CSS`, `escapeHtml`, `timeAgo`, `domainOf`).
- `js/charts.js` — `drawChart` / `resizeAll` wrapper around Chart.js; shared `gridOpt` / `baseOpts`.
- `js/auth.js` — `signIn`, `showApp`.
- `js/nav.js` — bottom-nav tab switching with **per-section lazy loading** (`import('./dashboard.js')` inside `LOADERS`).
- `js/app.js` — bootstrap: wires listeners, checks existing session, boots the app.
- `js/quicklog.js` — quick-log taps + the log-sheet modal (writes to Supabase tables).
- `js/dashboard.js` — per-section loaders over a shared 28-day `getCache()` (single `Promise.all` fetch).
- `js/cards.js` — "World" tab cards: briefing, insights, feed, projects, calendar, Hacker News (GitHub + HN APIs).
- `js/history.js` — steps history card with 24H / 7D / 30D range toggle.
- `.hermes/config.yml` — Hermes Orchestration Protocol config (gates, do-not-touch, routing).
- `docs/STATE.md` — Hermes protocol state.
- `.understand-anything/knowledge-graph.json` — knowledge graph generated by `/understand`.

## Conventions

- **ES modules only.** Use `import`/`export`; no globals leaking across files. Import shared helpers from `js/utils.js` rather than re-implementing them.
- **Supabase access goes through `sb`** from `js/config.js`. Tables referenced: `sleep`, `body_metrics`, `daily_state`, `intake`, `meals`, `supplements`, `supplement_log`, `goals`, `training`, `briefings`, `insights`, `feed_items`, `projects`, `events`, `health_metrics`, `health_raw`. Schema lives remotely — do not invent local migrations.
- **Charts only via `drawChart(id, cfg)`** in `js/charts.js`; reuse `gridOpt`/`baseOpts` for consistent styling.
- **Budapest timezone** for all date bucketing (`budDay` / `budaFmt` in `js/utils.js`).
- **No raw `Text()`/unstyled markup** beyond the existing card/stat components; keep new UI inside the established `.card` / `.stat` / `.feed` patterns in `css/styles.css`.
- **Lazy-load sections.** New per-section data should be a `load<Section>()` export in `js/dashboard.js` wired into `LOADERS` in `js/nav.js` — not eagerly imported at boot.

## Local dev

- Serve statically (any static server). No install/build: `python3 -m http.server` from the repo root, then open `index.html`.
- `node --check js/*.js` validates syntax (this is what the Hermes `build`/`lint` gates run).

## Hermes protocol

- `.hermes/config.yml` is the repo-level source of truth for gates and one-way doors. Treat it as read-mostly; changing it needs explicit approval.
- Knowledge graph: run `/understand` (or `hermes-understand`) to refresh `.understand-anything/knowledge-graph.json`; `docs/GRAPH-INDEX.md` is regenerated from that file — do not hand-edit it.
